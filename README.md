# ESP32-S3 蓝牙 OLED 文字屏

微信小程序输入文字，经 BLE 发送到 ESP32-S3 N16R8，在 SSD1306 128×64 I²C OLED 上显示。

## 接线

**断电后接线，按模块上印刷的引脚名称连接，不要按排列顺序猜测。**

| OLED 引脚 | ESP32-S3 开发板 |
| --- | --- |
| VCC | 3V3 / 3.3V |
| GND | GND |
| SDA | GPIO8（板上通常标作 8） |
| SCL / SCK | GPIO9（板上通常标作 9） |

这里的 8、9 是 GPIO 编号，不是排针的第 8、9 个脚。此配置适用于这些脚已引出的普通 ESP32-S3 开发板；如果板上另有外设占用它们，在 `platformio.ini` 改 `OLED_SDA`、`OLED_SCL` 并同步改接线。使用 3.3V 供电，避免模块将 I²C 上拉到 5V。需要杜邦线四根。

## 编译和烧录

用 VS Code / PlatformIO 打开本目录，选择 `esp32-s3-n16r8` 环境，点击 Build，然后 Upload。配置已覆盖为 16 MB Flash + 8 MB OPI PSRAM。

```sh
pio run
pio device list
pio run --target upload --upload-port COM你的串口号
pio device monitor --baud 115200 --port COM你的串口号
```

如果系统没有 `pio` 命令，使用 PlatformIO 扩展的终端，或直接执行本机 PlatformIO 安装目录中的 `platformio.exe`。首次烧录无法进入下载模式时，按住 BOOT，点按 RST/EN，再松开 BOOT，然后上传。上传会替换板上的原固件。

启动时自动检查 `0x3C` 和 `0x3D`，检测成功后显示中文连接提示；串口输出 OLED 地址、SDA/SCL、BLE 名称、Flash/PSRAM 大小。若没有检测到屏幕，仍会广播蓝牙，小程序显示接线提示并禁止发送；修好接线后重启开发板。

## 微信小程序

1. 在微信开发者工具导入 `miniprogram/`，使用自己的小程序 AppID。源码中的 `touristappid` 仅用于界面预览，蓝牙需手机真机测试。
2. 如需保留公开源码里的占位 AppID，先运行 `python tools/prepare_wechat.py --appid 你的AppID`，然后导入 `.local/wechat/`。更新源码后重新运行脚本。
3. 在小程序后台配置蓝牙用途和用户隐私保护指引，使用有该 AppID 开发权限的微信账号预览。小程序提供原生隐私同意按钮。
4. 打开手机蓝牙，点击搜索，在下拉框中选择 `S3-OLED-XXXX`，确认后连接。无需在系统蓝牙设置中先配对。
5. 在输入框写字，在字体大小下拉框选择标准/2 倍/3 倍/4 倍，再选择显示效果和速度，点击“发送到屏幕”。收到开发板最终确认后显示发送成功和页数。“仅更新屏幕效果”只更改当前屏幕上的文字样式，不发送输入框草稿；“清屏”不删除草稿。

安卓机还可能需要微信的附近设备、定位权限或定位服务，按手机系统提示授权。模拟器可查看页面，不能代替真机蓝牙测试。

成功连接并通过文字屏协议校验后，小程序会在当前微信的本地存储中记住设备标识和名称。下次打开或返回页面，会先扫描、再自动连接上次的设备；查找失败后可在下拉框选择其他设备，也可点击“重连上次设备”重试。主动断开后，本次页面不再自动重连，方便更换设备。清除小程序数据、换手机或设备标识变化后需重新选择；不会仅凭相同名称自动连接其他设备。

### 真机搜索不到设备

- 如果点击搜索后按钮完全不变，先排查按钮事件和旧预览包。本次修正搜索按钮的 `disabled` 表达式，确保初始值是布尔值 `false`，而非空字符串；成功点击后应立即显示“正在搜索…”及步骤提示。这与扫描启动后列表为空是不同阶段的问题。
- iPhone 请检查系统“设置 → 隐私与安全性 → 蓝牙”中微信（或实际使用的企业微信）的权限，开启后重新打开小程序。iPhone 无需按安卓方式排查定位权限。
- 本项目是微信小程序，若在企业微信内打开，系统权限应授予**企业微信**；普通微信的权限不会代替企业微信的权限。先在两个客户端用同一份代码对照测试。
- 搜索持续 12 秒。未匹配文字屏时，页面会区分“未收到广播”和“发现其他设备但未找到文字屏”。设备计数包含当前蓝牙会话的缓存，只作排查线索，不代表权限检查结果。
- 若显示接口名及错误码，先处理该接口的失败。系统设置中的蓝牙/附近设备权限、小程序的蓝牙授权、隐私同意是不同层级；部分安卓还需定位服务及宿主的定位权限。页面“蓝牙权限设置”打开的是小程序设置，宿主权限需到手机系统设置修改。
- 页面同时保留“微信返回”的原始错误。若为 `api scope is not declared in the privacy agreement`，应由管理员在当前 AppID 的小程序管理后台“用户隐私保护指引”中声明蓝牙相关用途，待配置生效后重新预览；源码的 `permission.scope.bluetooth` 不能代替后台隐私声明。若为隐私授权未完成，检查隐私弹窗及后台指引；若为 `auth deny`，再检查小程序蓝牙授权和手机系统对微信的蓝牙权限。
- 若能发现其他设备，确认烧录本项目固件，串口有 `BLE ready: S3-OLED-XXXX`。关闭其他手机、电脑或 BLE 调试工具的连接，再复位开发板搜索。OLED 未接好不会阻止本项目固件广播。
- 扫描不传系统层 `services` 过滤，按设备名称 `S3-OLED-` 或广播服务 UUID 筛选；允许重复上报，兼容首次广播没有名称、后续扫描响应才补齐名称的情况。连接后仍检查服务及特征 UUID。
- 扫描结果收进原生下拉选择器，不在页面逐项铺开。选项显示设备名称、标识末六位及未识别标记；选择后校验文字屏服务，不兼容则断开，不发送文字。iPhone 的设备 ID 是系统标识，不应当作 MAC 地址。若看到开发板的旧名称，请核对烧录固件。
- 如果导入的是 `.local/wechat/` 副本，修改源码后必须重新运行 `tools/prepare_wechat.py` 并重新预览，否则手机仍运行旧代码。

单靠源码不能确定具体手机的权限状态、实际烧录版本和企业微信运行时兼容性。可用 BLE 调试工具做扫描对照（完成后断开连接），再结合页面错误和串口日志定位。

## 显示行为

- 使用 U8g2 文泉驿 12 像素 GB2312 字库，支持常用简体中文和英文、数字、标点。未覆盖的生僻字、繁体字和 emoji 显示为 `?`。
- 字体下拉提供标准 1 倍、大字 2 倍、特大 3 倍、超大 4 倍。标准每页 4 行、每行约 10 个汉字；2 倍每页 2 行、每行约 5 个汉字；3 倍每页 1 行、每行约 3 个汉字；4 倍每页 1 行、每行约 2 个汉字。放大按像素实现，更改大小后重新分页，输入中的换行保留。
- 显示效果：自动翻页、静态显示（只显示第一页）、闪烁、向上滚动。速度可选 1/3/5 秒；自动翻页按此间隔切页，闪烁以此为亮灭周期、每次亮起切下一页，向上滚动先停留此时长，再用此时长滚入下一页并循环。滚动帧率受 I²C 传输速度限制。
- 显示设置可单独应用，发送文字时也会先应用设置。设置和文字分别确认；若文字随后发送失败，旧文字保留，但已确认的显示设置不会回退。设置保留到开发板断电或重启，下次连接会读取开发板当前设置。
- 每次最多 512 个 UTF-8 字节，约 170 个汉字或 512 个 ASCII 字符。界面实时显示字节数。Windows 换行统一为 LF，制表符替换为两个空格。
- 空文本表示清屏；文字传输失败保留旧文字；只有完整、合法的文本提交后才替换屏幕内容。
- 文字不写入 Flash，断电后恢复启动提示。断线保留当前显示，下次发送从头开始。
- 接收暂存 10 秒无新包或 BLE 断开即失效。I²C 仅在启动时检测，运行中拔掉屏幕不能实时上报；重新连接硬件后请复位。ACK 表示固件已完成显示调用，不保证物理屏幕的每个像素状态。

## BLE 协议

| 项目 | UUID | 属性 |
| --- | --- | --- |
| Service | `b82c0001-6d6a-4b2e-ae8b-3d80b18a5100` | 服务 |
| Write | `b82c0002-6d6a-4b2e-ae8b-3d80b18a5100` | Write |
| Status | `b82c0003-6d6a-4b2e-ae8b-3d80b18a5100` | Read + Notify |

每个写包最多 20 字节：`A5 01 seq op offsetLE16 totalLE16 [payload]`。seq 为 1–255 循环；op=1 开始（offset=0，无 payload），op=2 数据（最多 12 字节），op=3 提交（offset=total，无 payload）。所有包携带相同 total，各包收到 ACK 后再写下一包。UTF-8 字节可以跨包，拼接完成后再校验。

显示设置包（op=4）为 12 字节：`A5 01 seq 04 00 00 00 00 scale effect intervalLE16`。scale=1–4；effect=0 自动翻页、1 静态、2 闪烁、3 向上滚动；interval 范围 500–10000 毫秒。有效设置包会丢弃未完成的文字接收缓存（屏幕文字保留），以允许中断后立即重试，ACK 的 received 固定为 0。客户端队列保证设置包不会插入正常的文字传输。

新版 ACK 为 15 字节：`5A 01 seq op result receivedLE16 oledReady pagesLE16 effectsVersion scale effect intervalLE16`，第 11 字节为效果能力版本：1 表示支持 1/2 倍，2 表示支持 1–4 倍。当前固件报告版本 2。
result：0 成功，1 格式错误，2 长度错误，3 顺序错误/超时失效，4 非法 UTF-8，5 未检测到 OLED，6 不支持的显示设置。连接时 Read 读取屏幕是否就绪及当前显示设置，读取结果由微信的特征值变化事件返回。

新版小程序仍识别旧固件的 10 字节 ACK，可使用默认大小和自动翻页发送普通文字；效果版本 1 可继续使用 1/2 倍及动态效果，3/4 倍需要更新固件。发送前会校验设备能力，防止把不支持的字体设置发给旧固件。新版固件应配套新版小程序使用。

本示例未启用 BLE 绑定或访问口令，附近的兼容客户端可以连接和更新文字。

## 验证

```sh
npm test
npm run test:firmware
pio run
```

JavaScript 测试覆盖 UTF-8、多包边界、字节上限、ACK 校验、错误重试、中途断线、显示设置和旧固件兼容。`test:firmware` 需要可在本机运行的 C++ 编译器（默认 `g++`，可用 `CXX` 环境变量指定），验证设置校验、逐像素放大、滚动帧组合和动画时序。编译通过不代表已在你的屏幕上验证。

若要运行微信模板渲染测试，设置 `WXML_COMPILER` 环境变量指向微信开发者工具自带的 `wcc.exe` 后再运行 `npm test`。未设置时渲染测试会明确跳过。它会检查发送按钮、设备下拉框、显示设置的可用条件和原生隐私授权事件。

真机验收：依次发送 `你好，ESP32！`、含手动换行的中英文、超过 4 行的文本，再清屏；确认无乱码、每 3 秒翻页、清屏成功。发送过程中断开蓝牙后重连并重新发送，确认旧内容不会被半包替换。

效果验收：烧录新版固件并重新预览小程序，选择 2 倍字体发送中英文，确认字形放大且分页完整；分别应用静态、闪烁和向上滚动，切换快/标准/慢三档，检查静态只显示第一页、闪烁亮灭、滚动末页回首。效果播放时清屏应立即清空，断开再连接应读回当前设置。这里只提供编译和逻辑验证，物理屏幕观感需按以上步骤验收。

## 公开源码与本地配置

公开配置仅使用 `touristappid` 占位。本地 AppID 副本保存在 `.local/wechat/`，与构建产物、编辑器配置、环境文件和密钥文件一起排除在 Git 提交之外。

```sh
git config core.hooksPath .githooks
npm run check:public
```

提交钩子检查实际暂存内容，发现明显的 AppID、凭据或个人路径时阻止提交，且不输出匹配到的敏感值。
